# M1 故事闭环实施计划

**目标：** 沿用 M0，完成一句话生成三故事、批次历史、选择、人工保存、导演修改建议、采用及失败恢复。本轮是 M1 故事子阶段；剧本与分镜不计入完成。

**依据：** PRD 01/03/05/06、R4 P01/P02、R5 的内容版本、建议采用和持久任务契约。用户已授权沿用现有设计直接实施。

**架构：** React 工作台通过 OpenAPI 调用 FastAPI；PostgreSQL 保存不可变内容版本、选择记录、对话及建议。Job/Outbox 交给 AI Worker；真实模型通过服务端配置的适配器访问，凭据不进入浏览器或任务快照。未知受理状态不自动重发。

## 执行与验收

- [x] 审查 M0、运行 `make test` / `make check`，保存审查记录、Git 基线标签。
- [x] 内容领域：迁移新增创意/故事及追加版本、选择记录、对话建议；测试跨项目隔离、并发修改 409、旧文保留、候选每页三份。
- [x] 真实文本任务：冻结源版本、提示词及模型配置；恰好三份非空且不同方向的故事。建议只保存结果，采用时校验目标与基准版本。非法 JSON 最多两次修正，仍失败不写候选。
- [x] 恢复：重复提交返回同任务；超时/中断为 unknown；明确失败允许新任务重试并保留原快照，unknown 再提交必须显式确认可能重复计费。成功历史不重做。
- [x] 前端：创意输入与指令、三候选翻页、故事编辑/选择、导演对话/建议采用、版本历史和任务恢复；刷新恢复服务端状态，冲突保留草稿。
- [ ] 真实供应商验收（阻塞于凭据尚未注入）；已通过的工程验证：先写失败测试，再实现；运行隔离数据库迁移和真实 Redis/Worker 测试、契约生成、构建、静态检查及浏览器交互。真实供应商验证单独记录，不用测试替身代替。

## 运行条件与交付边界

模型服务、模型名及凭据注入方式等待用户提供；不读取 `.env` 或输出密钥。常规开发、测试和本地 Git 保存继续推进；缺少凭据时不得将真实模型验收写为通过。
