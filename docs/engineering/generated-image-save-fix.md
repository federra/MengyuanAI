# 角色生图后保存禁用修复 · 2026-09-11

原因：生成图片已由后端持久化，EntityManager列表通过catalogImages显示当前版本的预览；但未将file_id放入草稿output_file_id。保存按钮依据changes.length，没有修改则禁用。现有8848项目只读接口确认存在有效生成图，实体output_file_id仍为空；隔离页面测试复现“图片可见但保存禁用”。

修复仅在前端：当前版本、未过期、尚未选用输出的生成图进入待保存草稿，保存继续走既有原子版本接口。已选图片、主动清除、视觉描述/输入参考图/三视图已修改、版本冲突及未知提交均不自动覆盖。图片人工确认与保存选用仍分开；不开新任务、不自动替用户保存。

验证：复现用例先失败后通过；20项相关页面回归通过，含保存输出ID、重新打开、过期保护、输入/输出分离、未知命令恢复、草稿冲突、跨项目隔离与四主题。前端构建及git diff --check通过。实际8848只读检查证据见evidence/generated-image-save/live.json与截图，所有API写入拦截，供应商调用0。

无需后端重启或数据库迁移，现有Vite页面热更新。用户刷新/重新打开角色管理，已有有效图片会显示为待保存；点击保存修改即可，不需重新生图。没有将测试结果写成用户视觉验收。
