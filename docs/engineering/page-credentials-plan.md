# 页面凭据配置与 M1 真实验收增量

用户明确授权：系统设置中输入模型密钥、服务端安全保存、连接测试，随后完成M1真实文本验收。基线8bfea3a，保留feat/m1-story-loop、M0标签与用户PRD工作区。

1. 复用模型配置，新增独立凭据写入/状态与已保存模型连接测试。密码框不进入浏览器草稿、不回显；成功保存后清空输入。模型或凭据修改使旧测试提示失效。
2. 本地单用户凭据使用认证加密；主密钥与加密文件置于独立私有目录，目录0700/文件0600，跨进程锁及原子替换。凭据不进入PG、模型/任务快照、媒体、日志或Git；元数据仅引用、版本、是否配置。文件凭据绑定目标地址，API/Worker统一读取；保留环境变量兼容。此机制依赖本机账户权限，不承诺抵御同账户恶意进程或主密钥同时失窃。
3. 服务端校验保存的精确模型路由并执行一次小型文本请求，有限超时/输出；屏蔽供应商错误正文和密钥输入验证回显，拒绝重定向，敏感请求校验来源。连接测试只证明该次调用，不宣称全部生成、M2/M3能力或M1通过。
4. 针对加密落盘、权限/并发、地址绑定、状态/错误无密钥、进程读取、连接测试及UI密码不落草稿做回归；保留既有49后端/19UI。独立审查后重启本机应用，用户在页面填密钥，代理仅读取配置状态。
5. 真实验收经生产API/Worker完成一句话三候选、选择/修改采用、剧本/分镜、人工编辑保存、版本和确认；检查JSON契约及过期建议拒绝。异常/unknown保留原任务，绝不自动重复付费；真实质量、耗时、用量和失败边界单独记录。凭据尚未提供期间不计真实通过。

普通备份继续只涵盖数据库和媒体，不复制主密钥/凭据目录；移机或密钥目录丢失需重新在页面录入。Compose将共享独立凭据卷；本机Docker未安装，不声明容器运行通过。

技术依据：[Fernet认证加密](https://cryptography.io/en/48.0.1/fernet/)、[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。用户已明确批准功能，按已有授权直接实施，不额外引入架构或部署范围。
