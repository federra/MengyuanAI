## 一、故事与验收

## 二、目标旅程与共享状态

一句话 + 写作 skill / 提示词 → 三个小说选题 → 小说详情与多轮修改 → 选定小说 + 剧本 skill / 提示词 → 剧本 → 自动质检与修复 → 确认 → 分镜 → 自动质检与修复 → 四类参考图 → 独立 TTS / 视频 → 成片与导出。小说入口直接从原文与剧本指令进入共用剧本页。

两条入口在剧本生成前合流，之后复用同一剧本页、质检报告/修复状态、分镜页、参考图与视频任务状态，避免维护两套后半程。用户可返回前序修改，返回不等于自动确认旧内容。

原旅程唯一确认痛点为外部 AI 质检搬运；改造后在项目内组合原文、当前版本和审核提示词，输出报告与建议，采纳并复检后继续。是否缩短总制作时间需真实试用验证。

## 三、交接与恢复契约

小说→剧本：保存原小说 ID/版本、选定指令、目标规格；修复快照增加原质检报告。剧本→分镜：保存确认剧本 ID、分镜版本和稳定镜头 ID。镜头→视频：保存四类参考图版本、提示词内 ID 对应关系；顺序模式追加前镜视频与末帧版本。

来源变化或旧报告到达时，不覆盖新版本；结构错误不显示质检通过。生成成功与用户确认分别记录。顺序模式出现前镜失败、尾帧读取失败或输入变化时暂停后续，修复后从有效断点继续；前镜重做则后续依赖尾帧的镜头待更新。独立模式不无故重做其他成功镜头。

后端以受校验 JSON 交换数据，密钥仅保存引用。状态与流程原型在 R2；后续 G4 继续细化供应商参数、错误码、输入限制、真实保存及导出，不因示例走通宣称上线。
