# 产品定义与目标

> G2 基础修订 v1.3｜2026-09-07。最新依据 E10：用户要求恢复两条入口，加入小说选题、双节点自动质检、独立 TTS 与尾帧顺序生成。此前单工作流决定被本次明确指令替代。

## 一、产品判断与依据

梦源AI面向短片制作者、营销视频创作者、发布者与运营者，将文字创作、对照质检和镜头生成放进一个工作台，提高生产效率与内容一致性。优先解决已知痛点：当前梦源AI基本可用，但质检需人工复制到外部 Web AI 对话，耗时明显；暂无实际耗时或效果数据，不能承诺提升比例。

证据：E01 最初短片创作需求；E02 PC Web、暂缓协作发布；E03 营销/剧情片、30–90 秒竖屏及配音字幕配乐；E04 自研系统与外部质检痛点；E05 模型/提示词配置；E06 深色参考、浅深切换与字号要求；E07 关键节点人工确认；E08 暂缓账号权限；E09 历史单工作流修订；E10 本次双入口、小说选题及镜头制作调整。E09 不再作为当前范围依据。

## 二、范围与工作流

PC Web；一句话和小说/故事两条入口，共用剧本、分镜、参考图、视频、成片页。默认 60 秒、9:16，可选 30/90 秒、16:9/1:1。暂不做参考视频再创作、账号权限、团队协作、发布运营、高级多轨剪辑。

一句话 + 写作 skill / 提示词 → 三个小说选题 → 小说详情与多轮修改 → 选定小说 + 剧本 skill / 提示词 → 剧本 → 自动质检与修复 → 确认 → 分镜 → 自动质检与修复 → 四类参考图 → 独立 TTS / 视频 → 成片与导出。小说入口直接从原文与剧本指令进入共用剧本页。

系统配置为创作必需支撑：各文本/质检/图像/视频/音频环节可分配模型；提示词中心与环节入口共用配置；写作和剧本各支持选择 skill 或提示词。此范围不等于现有梦源AI后台已实现这些能力。

## 三、目标与衡量

| 目标 | 指标口径 | 获取方式 |
| --- | --- | --- |
| O01 减少审核搬运 | 每部短片复制到外部 AI 的次数、准备/回写耗时 | 试用前后同任务观察，目标是主路径无需外部复制 |
| O02 提高完成效率 | 从输入到可导出作品的总时长、两入口完成率 | 按入口、片长、人工等待/模型等待拆分 |
| O03 保持内容一致 | 审核问题命中/漏报、人工采纳率、上游变更导致的返工镜头数 | 人工抽检小说→剧本及剧本→分镜，避免以零报告等同高质量 |
| O04 可控调用 | 配置失败率、任务版本可追溯率、局部恢复成功率 | 调用日志与任务快照，顺序链单独统计尾帧失败 |
| O05 清晰操作 | 核心操作完成率、误点与找入口耗时、两主题可读性问题 | 原型走查与试用反馈 |

尚无基线数据或承诺阈值；用相同内容、模型和片长对比，剔除演示结果，避免把生成快等同创作质量高。

## 四、约束与待细化

AI 输出必须可编辑、可追溯；两次质检带入对应原文和内容版本，修复后复检，再由用户确认。参考图在视频生成前确认；任务使用提交快照。用户更换小说、剧本或镜头时保留旧成果并标记影响，不静默覆写。

供应商、模型能力、真实 skill 格式、长小说输入上限、音频时间对齐与导出参数未确定；正式模块将按实际服务能力定义。示例按字数估算篇幅，真实系统应结合动作时长、对白语速和镜头时长判断，不用硬截字代替改编。R2 为可操作原型，真实生成和成片编码尚未接入。
