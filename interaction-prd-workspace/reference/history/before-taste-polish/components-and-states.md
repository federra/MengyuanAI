# 主线原型与组件状态

> R2 修订包 v3｜2026-09-07。按用户最新工作流要求直接更新；替代此前单工作流原型。G4 正式模块仍按计划逐一细化，不因本参考原型完成而自动通过。

## 一、当前范围与入口

PC Web；一句话和小说/故事两条入口，共用剧本、分镜、参考图、视频、成片页。默认 60 秒、9:16，可选 30/90 秒、16:9/1:1。暂不做参考视频再创作、账号权限、团队协作、发布运营、高级多轨剪辑。

一句话 + 写作 skill / 提示词 → 三个小说选题 → 小说详情与多轮修改 → 选定小说 + 剧本 skill / 提示词 → 剧本 → 自动质检与修复 → 确认 → 分镜 → 自动质检与修复 → 四类参考图 → 独立 TTS / 视频 → 成片与导出。小说入口直接从原文与剧本指令进入共用剧本页。

原型页面：creation「双入口与小说选题」、script「共用剧本与自动质检」、storyboard「独立分镜与质检」、finishing「成片与导出」。顶部四步导航允许返回已完成步骤；提前进入未准备阶段时提供前置条件提示。系统、提示词、音频模型和风格模板统一收在右上角「配置」，主题切换单独保留。

## 二、页面行为与验收

| 页面 / 规则 | 前置、触发与结果 | 异常与恢复 |
| --- | --- | --- |
| creation / F01 初始设置 | 选择类型、风格、时长、画幅；一句话入口选择写作 skill 或提示词，小说入口选择剧本 skill 或提示词 | 空输入不能提交；改规格保留旧成果并使下游待更新 |
| creation / F02 三选题 | 生成三个不同剧情方向，每卡包含标题和一句话故事；点击打开全文弹层 | 示例按目标时长限制篇幅；旧时长选题不能直接作为新时长小说选定 |
| creation / F03 小说详情 | 全文可编辑；多轮要求产生新版本和历史；关闭保留编辑，选定后生成剧本；卡片区支持额外新选题 | 空小说或空修改要求提示补充；未选定不能进入后续生成 |
| script / F04 小说转剧本 | 剧本指令二选一；从选定小说或输入故事生成，自动运行小说→剧本质检 | 来源/规格变化需重新生成，旧审核不能确认新版本 |
| script / F05 质检修复 | 简报覆盖剧情贴合、人物情绪和内部连贯性；修复任务携带原小说、当前剧本、质检报告和指令；复检后确认进入分镜 | 手改剧本立即作废审核；修复保存新版本，保留无关人工编辑 |
| storyboard / F06 共用分镜 | 列为序号、台词、角色/场景/道具/站位、提示词、视频、独立音频、操作；新增/删除/移动归入更多菜单 | 至少保留一镜；增删或修改后重新质检，下游依赖结果待更新 |
| storyboard / F07 对照质检 | 自动对照确认剧本，显示简报与建议版；校验后采用并自动复检，人工确认 | 报告须匹配来源剧本、分镜版本、合法镜头/图片 ID；非法结构不能部分写入 |
| storyboard / F08 图片引用 | 四类图均可生成、修改描述、上传和确认；提示词插入引用后显示可点击标签 | 稳定 assetId 关联图片，改名不会串图；未知引用阻止保存/生成 |
| storyboard / F09 独立音频 | 每镜台词单独提交 TTS，与视频独立；提示词中心有音频模型页，记录音色、文本和配置快照 | 空台词禁止提交；台词变更使旧音频待更新 |
| storyboard / F10 顺序视频 | 可选独立生成或按顺序生成；后一镜等前一镜视频与尾帧成功后再提交，四类图仍共同输入 | 尾帧无效/镜头失败暂停后续，保留成功结果并支持继续；改动前镜使依赖链过期 |
| finishing / F11 成片 | 按独立成片顺序和时长预览，配置字幕、配音、配乐，检查缺失/过期视频后导出 | 调整顺序提醒衔接影响；原型只输出项目 JSON 和演示反馈 |

## 三、公共组件与状态

视觉沿用用户深蓝参考，浅/深主题共用结构。正文、输入、按钮 15px，辅助 13–14px，区块标题 18px，页面标题 24px。顶栏只留配置与主题；分镜次要动作收进每行更多菜单。表格在本地容器横向滚动，不挤压成不可阅读的小字。

新增公共组件：选题卡、小说详情双栏、skill/提示词二选一及折叠指令编辑、紧凑质检报告、四类图片网格、可预览的 @图片标签、独立 TTS 状态、顺序生成进度与前镜尾帧标签。components 展示公共样式；states 集中展示待选择、审核失败、引用失效、尾帧等待/失败与恢复，并保留原有加载、未保存、过期和部分失败示例。

状态链：小说未选定/修改中/选定 → 剧本生成中/自动质检/待修复/复检/待确认 → 分镜同类审核状态 → 参考图缺失/待确认/确认 → 视频未开始/生成中/等待尾帧/暂停/失败/完成/输入过期。生成成功、审核完成、用户确认三者分别记录。

## 四、数据契约与交付边界

建议后台用 JSON + JSON Schema 校验，显式保存 schemaVersion、sourceNovelId/version、scriptId/version、baseBoardVersion、issues、proposedShots。采用建议前按版本与稳定 ID 校验，在同一事务创建新版本；不依赖模型返回的自然语言定位或直接覆盖当前内容。长小说需先做章节/人物/事件映射，再按片长改编；具体拆分策略待服务选型细化。

镜头图片引用存 assetId 与版本，显示名称只用于阅读；提交时展开为模型支持的媒体块，并保存标签→媒体位置映射。顺序任务还保存 previousVideoId、tailFrameId、前镜视频版本、四类参考图版本与提示词/模型快照。帧提取失败时不能无图继续，也不能借用旧视频尾帧。重新生成前镜应使依赖尾帧的后续任务待更新。

原型使用本浏览器 v3 独立示例存储；原有 v2 数据未覆盖。AI 小说、剧本、审核、图片、TTS、视频均为明确标注的交互示例；skill 是可编辑示例指令，尚未接真实 skill 执行器。浏览器朗读不是模型音频文件；示例视频无真实 MP4。上传视频的末帧读取仅为浏览器实现，实际服务需编码兼容性验证。篇幅 2–4 字/秒是原型估算，不是实际成片时长保证。
