# 产品定义与目标

> G2 审核稿 v1.0｜依据：已确认的 G0 v0.4、双主题及字号补充、已确认的 G1 v1.1。状态：待 G2 审核。

## 一、产品定义与问题依据

梦源AI 是面向短片制作者、营销内容生产者和运营者的 PC Web 创作系统，将一句话创意、故事文本或参考视频转为可审核、可编辑的分镜，经风格与参考素材、镜头视频、声音和基础剪辑形成可导出短片。首版同时支持营销和剧情短片，默认目标为 30–90 秒竖屏；默认值不是已确认的硬性时长或画幅限制。

当前优先解决的问题是质检依赖外部 Web AI：用户要搬运剧本或分镜并组织审核上下文。目标体验是直接在项目内发起对照审核、定位问题、预览修改并复检。现有自研系统“基本可用”为用户自述，尚未核验代码、接口及具体功能覆盖，不能据此估算改造成本。

| 证据 ID | 来源与已知事实 | 使用边界 |
| --- | --- | --- |
| E01 | 用户原始需求：三入口、内置质检、可编辑分镜、风格模板、参考图、视频和导出 | 是产品意图，不是实现验收结果 |
| E02 | 用户确认 PC Web、关键节点人工确认，暂缓协作/发布/运营分析 | 作为首版边界 |
| E03 | 用户确认营销与剧情均支持、默认 30–90 秒竖屏，包含配音/字幕/配乐及顺序/时长调整 | 音频来源与输出规格未细化 |
| E04 | 用户自述：制作者使用自研梦源AI，质检需复制到外部 Web AI，较耗时 | 没有耗时、成本或完成率实测 |
| E05 | 用户要求模型按环节配置，所有模型交互步骤支持自定义提示词；G0 确认中心加就地入口方案 | 不代表任何特定供应商已接入 |
| E06 | 用户提供暗色角色设置截图，随后要求浅/深切换按钮和醒目适中字号 | 精确字体与颜色在 G3 定稿 |
| E07 | 用户确认 G0 v0.4 与 G1 v1.1，包含版本追溯、局部重试、项目覆盖等设计规则 | 是设计决策，仍需原型及实现验证 |

上述事实来源均为本次对话及工作区保留的输入/确认记录；“用户需要控制感”“减少返工提高满意度”等属于推断，不作为调研事实。

## 二、价值、目标与非目标

对制作者，减少质检搬运与修订定位成本，保留内容控制权；对运营者，复用参考视频结构并形成自己的作品；对产品经营方，提供可重复使用的创作流程和配置能力。留存、收入或传播增长尚无数据，不承诺由本方案带来。

| 目标 ID | 用户可观察结果 | 对应衡量 |
| --- | --- | --- |
| O01 | 从当前项目直接完成审核和意见处理，无须外部粘贴 | M01、M02 |
| O02 | 三种来源均能走到可预览、可导出的成片 | M03、M04 |
| O03 | 发现信息遗漏、人物差异、情绪和动作问题，并追踪修改后的影响 | M05、M06 |
| O04 | 各环节模型和提示词可调，运行结果能追溯输入配置 | 配置及任务版本验收；无效配置可在运行前修复 |
| O05 | 创作和配置页面提供两种主题，长文清楚可读 | 主题切换、状态保持及字号验收 |

本期不包含团队协作/审批、平台直接发布、发布排期、运营分析、高级多轨剪辑、模板市场或训练基础模型；不承诺参考视频的传播效果。PRD 和原型交付不等于接入真实模型、部署生产系统或完成现有系统迁移。

## 三、首版能力与全局约束

创作入口：一句话通过多轮引导形成剧本；故事文本生成剧本并对照原文审核；参考视频先拆解为带时间码的分镜及结构洞察，再结合用户想法或参考图生成新分镜。故事路径继续做剧本与分镜质检；再创作路径检查用户意图和借鉴点，不要求新片忠实复制竞品剧情。

共用制作：可编辑分镜 → 对照审核/修改/复检 → 用户确认 → 风格或自定义模板 → 角色、场景、道具、站位参考图 → 用户选用确认 → 镜头视频候选 → 配音/字幕/配乐及顺序/时长调整 → 整片预览与导出。剧本、分镜、参考图是人工确认节点；竞品入口没有独立剧本时不凭空增加剧本确认。生成成功、审核完成、审核通过和用户确认是不同状态。

配置：系统页集中维护模型连接、能力、参数及环节分配，生成和审核可选不同模型。提示词中心维护默认版本，环节内编辑默认仅覆盖当前项目，显式设为默认才更新默认配置；运行前能看到生效来源和实际输入。变量、输出结构、能力类型需要校验；手动选风格或保存已有模板等非模型操作不额外制造提示词步骤。所有实际模型调用，包括 AI 风格辅助、模板建立和声音处理，均须映射到可配置步骤。

版本与权限：首版按单使用者工作区建模，项目所有者可编辑、确认和导出，配置所有者管理自己的连接与默认提示词；多人共享部署权限在 05 模块定稿前补齐。任务绑定提交时的输入、模型、提示词和参数版本；后续保存只影响新提交任务，排队/运行任务和既有结果不自动更新。上游修改保存新版本并标记受影响内容，不静默覆盖旧成果；失败重试保留成功素材。凭据以掩码显示，内容快照和导出不包含密钥明文。

视觉：全局按钮切换浅/深主题，深色承接用户参考；建议跨页/刷新保持选择，切换不丢输入或干扰任务，原始图片、视频及导出不随界面反色。字体必须醒目适中；16px 正文/输入、辅助不低于 14px 是 G3 候选，不是用户指定的精确数值。长内容用换行、展开或滚动承载。

## 四、成功指标与验证方式

先验证质检流程能在系统内完成，再衡量效率与质量。以下统计方案为 G2 建议；没有既有基线，不设置虚构的提效百分比。试用结果按入口和内容长度/目标时长分组；任务时间与用户操作时间分开。

| 指标 | 定义及样本边界 | 基线/目标 | 来源与观察方式 |
| --- | --- | --- | --- |
| M01 质检人工耗时 | 从开始准备一次审核到处理完该轮意见的用户操作时长；剔除模型等待及中断时长 | 基线未测；目标在配对试用后设定 | 同等内容的现有流程/新流程任务观察；建议报告中位数及样本数 |
| M02 质检外部复制次数 | 一次审核周期中为完成审核而手动跨工具复制内容的次数；不计用户主动备份 | 主路径验收目标 0 次；现状未测 | 可用性测试观察与用户记录，不依赖读取剪贴板 |
| M03 首次成片耗时 | 项目创建到首次成功导出的自然时长，另列用户操作与任务等待 | 基线和目标未定 | 项目/任务/导出记录；试用按周查看已完成样本 |
| M04 7 日成片完成率 | 创建后 7 日内成功导出的非空生产项目 / 同批非空生产项目；只纳入已满 7 日的项目，重试不重复计数，排除明确标记的测试项目 | 7 日窗口为测量建议；目标未定 | 创建批次统计；失败与放弃项目保留分母，按入口分组 |
| M05 镜头首次采纳率 | 首次生成候选被用户确认选入成片的镜头 / 至少一次生成成功的镜头；完全失败另报，不混入分母 | 基线和目标未定 | 镜头任务与成片引用；同时报告失败镜头数量 |
| M06 审核质量 | 人工复核样本中的遗漏/人物/情绪/动作问题数、AI 命中数、误报数及修改后残留问题；按类型分别看 | 基线和目标未定；不以 AI 自评分替代验收 | 用原文、剧本和分镜进行人工对照；产品负责人组织样本复核 |

由产品负责人组织试用及口径确认，研发在真实实现阶段记录事件，测试/制作者复核样本；这些是责任建议，不新增系统内团队角色或运营看板。后续样本量与采样周期确定后再设量化目标。
