# 用户与需求分析

> G2 审核稿 v1.0｜需求依据为产品定义中的 E01–E07；以用户陈述与已确认设计为依据，尚无独立访谈或实测数据。

## 一、角色、场景与决策关系

| 角色 | 情境与目标 | 决策/权限边界 | 依据 |
| --- | --- | --- | --- |
| 短片制作者（主要实际使用者） | 用梦源AI写作、生成素材和成片，减少质检搬运 | 首版作为项目所有者决定内容修改、素材选用、确认和导出 | E01、E04、E07 |
| 营销内容生产者 | 从创意或故事出发，保留传播信息与表达目的 | 首版不另建审批角色；可与制作者是同一人 | E01、E03；具体客户审批关系未提供 |
| 内容发布者/运营者 | 学习参考视频的结构和节奏，形成自身作品 | 可作为创作用户；发布平台、账号排期及运营分析不在首版 | E01、E02 |
| 配置所有者 | 配置连接、环节模型和默认提示词 | 单使用者工作区可与制作者是同一人；不据此虚构多人管理员 | E05、E07 |

购买者、团队领导、客户审片人和终端观众的行为证据尚缺。观众受到成片质量影响，但不是本期创作工作台的操作角色；不为未确认人群新增管理功能。

## 二、现状、痛点与用户任务

已确认现状是“自研梦源AI基本可用 + 外部 Web AI 做质检”。用户把需要审核的内容复制到外部对话，这一步耗时（E04）；如何准备审核指令、如何将结果回写以及当前剪辑/声音工具，均未明确，不能写成既有使用事实。

关键任务：当剧本或分镜准备好时，制作者希望在项目内完成对照审核、定位问题并修订，从而减少上下文搬运。创意入口需要把模糊想法变成可生成的镜头；故事入口需要保留原作要点；参考入口需要借鉴结构并表达自己的主题（E01）。

动机推断：功能层面要获得可用短片；情感层面可能希望减少等待和不可控感；社会层面可能需要按期交付。后两项尚未访谈验证。新方案吸引力是减少重复操作；可能的顾虑包括审核可信度、生成成本和局部修改能否保留成果；既有梦源AI习惯是需要兼容的背景，而不是要求用户整体换工具的依据。

## 四、特殊情境与可访问性

首次或低频使用者需要看懂三入口差别、当前阶段、模型缺失原因和下一步动作；专业使用者能打开提示词设置和局部修改，不被强制重新走完整向导。高压交付下优先保留已完成素材、指出失败镜头并给出恢复入口。这些是设计响应，未作为真实用户访谈结论。

全局主题按钮应有可读文案和键盘操作；两主题的表格、表单、提示、弹层与错误状态保持可读。字号与行高在 G3 确认，主要内容不靠小字压缩；长剧本、提示词和审核意见允许展开、滚动并保留焦点。浏览器放大后关键操作仍可访问。

弱网或离线时区分“本地仍在编辑”与“已成功保存”，保存失败保留内容并允许重试；不把离线排队或后台服务可用性当成已经实现。无权访问的项目或配置不给出内容、明文凭据及可执行修改入口；仅隐藏按钮不是权限规则。首版以 PC Web 为产品平台，不用一个自适应页冒充手机端独立原型。

## 五、分析结论与待验证项

优先保证 N04 的系统内审核闭环，并由 N13/N14 提供可调模型与提示词；其余主流程让质检结果能够继续转为成片。N12 仍是首版承诺，交付排在共用链路之后仅为依赖顺序。

尚需验证：审核准备和回写实际耗时、用户对审核意见的处理习惯、是否存在多人共享部署、具体模型/音频工具和容忍等待时间。按 01 的 D01–D06 在对应模块及试用阶段收敛；不要求用户重新填写已确认的范围或视觉偏好。
