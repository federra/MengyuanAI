# V9 具名方法、双库与操作对齐

2026-09-08，依据用户本轮明确修改更新独立 PRD 和 Demo。本轮未修改生产工程，不改变 M0/M1 已验收事实。

## 一、已调整的产品规则

1. 各工作台底部统一纵向对齐：方法选择→查看/配置→生成按钮，同宽同左边缘；助手采用相同布局。创意助手没有方法选择，从故事助手开始分别使用写作、剧本、分镜生成方法。
2. 方法菜单显示具体名称，示例含人物弧光故事法、悬念反转故事法、三幕分场剧本法、忠于原作改编法、连续动作分镜法、画面节奏分镜法。每项关联稳定ID的Skill或提示词模板，按适用环节过滤。
3. 资产增加Skill库、提示词库。Skill可新增、编辑、导入Markdown/TXT并用于项目；提示词与配置中心共用同一模板及版本，支持新增、编辑、项目覆盖与恢复继承。
4. 右上角统一“设置”，进入提示词、大模型、音频和风格配置。质量建议可不采用的V8规则继续保留。

## 二、数据与工程交接

资源ID、适用阶段、来源类型、资源版本、有效正文和项目覆盖一起进入调用快照。库中更新供后续任务使用，历史快照不变。保留旧版自定义方法正文；上传Skill只作为文本，不执行代码。正式资源表、版本接口和项目绑定按R5的V9增量实现，不能用Demo浏览器存储作为生产数据库。

提示词工程规则见R4，页面行为见05/06/07/08正式PRD；设计与公共状态见R1/R2。资产及设置流程图的Mermaid与SVG同步更新。

## 三、验证

- `node reference/tests/workbenches-v9.mjs`：具名资源、阶段约束、版本快照、必填变量与项目覆盖。

- V5/V8状态回归、V8浏览器主链、manifest校验继续执行；浏览器测试需要本地4173、Playwright与Chrome，可通过`PLAYWRIGHT_MODULE`和`CHROME_PATH`指定已安装运行时。
