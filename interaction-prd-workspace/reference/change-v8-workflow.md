# V8 工作流调整与工程交接

2026-09-08，依据用户最新决策同步正式 PRD、交互原型、标注、提示词清单与技术规划。本次没有修改生产前后端、数据库或已交付 M0/M1 实现。

## 一、当前规则

1. 立项选择画幅比例与分辨率，视频生成与导出继承；生成设置统一修改，不再首次进入分镜时自动弹窗。旧项目只补缺省值，保留既有规格。
2. 主操作先选方法再生成：创意为写作方法，故事为剧本方法，剧本为分镜生成方法。助手使用对应上游共用方法：创意/故事→写作，剧本→剧本，分镜→分镜生成。配置与调用快照一致。
3. 故事、剧本、分镜的 AI 质检仅建议修改。即使质检有问题、失败、尚未完成或报告过期，用户仍可保留当前版本继续。用户决定与 AI 报告分开保存，不伪造质检通过；空内容、版本冲突、无效引用、缺失文件等执行错误仍明确提示。故事原本没有强制检查门槛，本轮不新增强制检查阶段。
4. 分镜助手可多次“生成分镜表”，每次刷新整张表并保留旧版；质检结果常驻助手，可按建议修改或直接继续。图片按角色、场景、道具、站位四类纵排，同类图片堆叠。
5. 第二镜起可“参考上一视频尾帧”：前镜未生成时禁用，取帧成功显示角落缩略图并插入精确图片引用；重复点击不重复绑定，前镜更换后旧引用过期。原型生成视频与尾帧是示例，上传视频可读取真实末帧。

## 二、工程实施范围

按 R5 的 V8 增量实现项目规格字段、共用方法绑定、review_decisions、非阻断质检状态、分镜版本替换与前镜尾帧引用接口。对现有 M0/M1 做增量迁移和回归，不从头重跑里程碑。当前生产工程仍以原验收记录为准；这份变更说明不能作为真实 AI 或成片已完成的证据。

## 三、验证入口与边界

- `npm run validate`：文档索引、页面关系和标注结构。
- `node reference/tests/workbenches-v5.mjs`：原有 TXT、台词、修复与任务依赖回归。
- `node reference/tests/workbenches-v8.mjs`：方法快照、规格继承、精确尾帧引用、过期依赖、质检建议可继续、执行错误仍拒绝。
- `node reference/tests/workbenches-v8-browser.mjs`：需本地4173服务、Playwright和Chrome；使用隔离浏览器与示例数据，验证实际按钮链路。
