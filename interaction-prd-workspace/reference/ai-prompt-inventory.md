# R4 AI 交互与提示词定制清单

本清单是首批提示词工程交付范围，包含28个交互点。“已演示”仅表示原型有交互，不代表已调用真实AI。可读取同目录 ai-prompt-inventory.json 作为机器清单。

## 一、全局契约

每个请求必须携带 projectId、market/targetLanguage、promptId/promptVersion、modelConfigVersion、sourceIds/sourceVersions、用户要求、输入素材。用户输入及上传文本放入数据区，不能覆盖系统约束。模型输出先解析、校验，再写新版本；不直接覆盖已确认内容。

提示词工程师每项交付：system模板、user模板、变量字典（类型/必填/默认）、输出JSON Schema、2个中文与2个英文正例、至少3个失败反例、质量评分标准和版本说明。故事/剧本/质检优先完成，随后镜头与媒体；可选增强项不阻塞主链。

## 二、优先级与配置映射

P0主链：P01–P08、P11–P13、P15、P17、P18、P26–P28（P25仅保留历史）。P1增强：P09、P10、P14、P16、P19–P21。P2可选：P22–P24。系统按独立交互key登记模型和提示词，细分模板通过上述key独立登记；故事修改、剧本修复、分镜修复不能只靠重新生成的通用模板。图像类按资产kind分派，不要求采用同一个供应商。

图像、视频、TTS接口通常是文字与结构化参数并存，不能把音色、画幅、时长、参考图URI全部塞进一段提示词。TTS供应商不支持自由指令时使用text/voiceId/speed等参数，不伪造“系统提示词”能力。

## 三、关键结构示例

故事批次：
```json
{"schemaVersion":1,"batchId":"batch-1","storyCount":3,"stories":[{"id":"s1","title":"...","logline":"...","direction":"重逢","text":"...","estimatedSeconds":55},{"id":"s2","title":"...","logline":"...","direction":"悬念","text":"...","estimatedSeconds":62},{"id":"s3","title":"...","logline":"...","direction":"抉择","text":"...","estimatedSeconds":48}]}
```

质检报告：
```json
{"schemaVersion":2,"scriptId":"script-2","baseBoardVersion":3,"summary":"动作衔接遗漏","issues":[{"id":"issue-1","shotId":"shot-2","type":"action","severity":"major","evidence":"原剧本先取出包裹再递交","suggestion":"补齐取件动作"}],"proposedShots":[{"id":"shot-2","dialogue":"快递员：老师，这是给您的。","dialogues":[{"id":"line-1","speaker":"快递员","emotion":"真诚","text":"老师，这是给您的。","voice":"warm-1"}],"prompt":"先取件再递交 @[asset-1]"}]}
```

上例仅展示单镜，真实 proposedShots 必须包含完整镜头集合。写入前校验源版本一致、ID无重复/遗漏、引用存在、字段类型合法。结构不合法时返回校验反馈让模型重试，有限次数后显示错误并保留原内容。

修复请求必须包含原文、当前版、报告全文和基准版本。重复应用相同报告应无副作用；内容版本已变则拒绝应用。报告说明“无问题”并不代表人工审片可以省略。

## 四、不需要提示词的环节

项目统计、TXT读取（选题语义提炼另见P26）、分页/排序、版本保存、任务日志、图片ID解析、视频末帧截图、音频时间对齐、SRT生成、视频编码与下载均由确定性程序完成。字幕翻译/润色才需要语言模型；字幕时间戳不应由大模型猜测。不要为这些工具步骤采购无必要的提示词。

## 五、统一验收用例

中文与英文市场分别验证输出语言；导入原文不被覆盖。输入包含“忽略系统要求”等文本时仍按内容数据处理。长故事不得静默截断；人物/道具同名时依赖ID。缺图、缺模型能力、无合法尾帧、JSON错误、超时都应有明确失败返回。中途修改配置后，已发任务仍使用发起时快照。每个模板注明适用模型能力与变量边界，禁止把示例占位符当作有效素材URI。

首个本地工程验证优先接入一句话主链；P26为随后接入的TXT入口，产品范围继续保留。P10可先用人工建立元素清单，P19可先用上传配乐；自动化增强不阻塞真实成片。输出校验、服务端ID分配、配置快照与落库契约见 [R5 技术实现规划](/content/reference/technical-implementation-plan.md)。


## M1 故事工程接入 · 2026-09-08

## V8 方法共用与质检边界

创意助手已从当前UI移除，P25仅保留历史契约、不再从创意页发起；故事助手与创意主工作区共用写作方法；故事生成剧本与剧本助手共用剧本方法；剧本生成分镜与分镜助手共用分镜生成方法。各自interactionKey仍独立，任务冻结本次方法版本。质检及修复提示词应描述问题、依据、修改建议，不输出强迫用户修改或禁止推进的产品指令。AI报告不是工作流授权结果；报告未采用时原结论保留，由应用记录用户选择继续。尾帧通过稳定refId与图片输入序列对应，提示词不得虚构已存在的前镜图。

## V9 具名方法契约

具名方法绑定单个Skill或提示词模板，以resourceId、resourceVersion、kind、stage定位，禁止根据显示名或类型猜选。故事/剧本/分镜主生成及对应修改记录所选方法和本次实际正文；历史创意导演对话P25保留原交互模板与快照，当前页面不再发起调用。模板库为配置中心与资产库的同一数据源，项目覆盖独立保存。模型请求组合操作模板、选中方法、源文本、用户要求和报告上下文；instruction为用户本轮额外要求，不递归拼接模板自身。

本轮只实现原型的资源管理与调用快照，未执行真实Skill或模型。


V10 配置路由：每个交互按 text/image/video/audio 分类，类别设一项默认模型，环节可覆盖；TTS 与配乐归 audio，声音设定推荐归 text。每个提示词场景绑定模板 resourceId，支持系统默认与项目覆盖，模板库与资产库同源。任务冻结类别、路由来源、模型参数、场景模板 ID/版本/正文及覆盖版本；工作台选定方法作为独立 method 上下文保留。

## V12 P01 数量与篇幅契约

新增变量 `{{storyCount}}`：integer，范围1～3，默认3；客户端与服务端分别校验。模板按实际值要求输出 stories 数组，应用侧验证其长度严格等于请求数量；不足或超量均进入结构纠错，不静默补齐或截断。完整创意中的字数要求作为用户写作要求传入，明确要求优先于示例时长预算；不把字数要求当系统指令。若要求不可兼顾，在任务结果提示原因，不擅自丢弃原文。

旧项目缺字段默认3；旧模板和Skill保留原版本，任务请求额外冻结 applicationConstraints.storyCount 和 sourceIdea，应用约束覆盖模板中写死的数量。新建/保存的故事提示词模板必须有 storyCount 变量；历史任务不可重写。补充中英文各1/2/3份、越界/小数、模板写死三份但请求一份、明确字数要求、生成中改配置、TXT单卡等用例。原型仅验证参数与示例数量，不代表真实模型字数遵循已验收。

## V13 分镜与视频提示词

P16/P17输入增加项目所选风格的有效正文与版本、绑定lineId及完整台词/角色/情绪、assetId及确切图片版本、单镜模型/比例/尺寸/秒数/分辨率。应用编译“镜头描述 + 风格指导 + 图片引用映射 + 绑定台词”，生成前展示可复核内容，冻结最终请求；不能只发送风格名称或旧台词副本。TTS仅接受当前lineId对应台词，独立变更和重试；视频模型原生声音与独立TTS的输出选择由导出轨道控制，避免双声叠加。

JSON导入是确定性解析、结构校验与事务替换，不需要调用AI重新生成导入内容。后续质检可调用既有P06，但报告只建议修改，不是导入成功的前置条件。AI分镜输出仍遵循后端BoardBody v2；用户导入包v1经适配器转换，不能直接作为内部数据。首批新增用例：同名图片不同ID、台词改写后绑定同步、风格改版、单镜规格覆盖、并行与尾帧互斥、非法导入不写入、合法导入整表刷新。
