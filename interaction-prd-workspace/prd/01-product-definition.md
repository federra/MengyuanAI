# 产品定义与目标

AI短片工坊是面向短片制作者的 PC Web 创作系统，帮助营销视频和剧情短片创作者把创意或已有故事转成可制作的镜头和成片。核心目标是以一套流畅、简洁的系统贯通从创意到成片的生产过程，降低环节衔接、重复操作、素材管理和返工成本，整体提升短片生产效率与成片质量。内置质检是保障内容一致性、减少返工的辅助机制，不作为产品的首要价值主张。

## 产品结构

左侧固定五个模块：项目、创作、资产、任务记录、系统设置。创作包含顶部五个阶段：创意 → 故事 → 剧本 → 分镜 → 导出。两条入口共用后续阶段，不建立两套编辑器。

项目设置名称、可扩展类型、中文/英文市场、视觉风格。创建阶段不设置固定时长；故事可按内容估计时长，最终时长以分镜及剪辑累计为准。创建时选择画幅比例与分辨率，后续视频生成和导出继承项目规格；生成设置可统一调整规格及模型。

## 首版范围

包含项目隔离、1～3份可选数量的故事候选及历史分页、故事对话修改、剧本自动质检与修复、分镜编辑与质检、四类核心参考图、独立 TTS、视频顺序生成、基础剪辑与导出、资产复用、任务追踪、模型/提示词/风格配置。

本地验证阶段不建设复杂权限体系、团队审批、订阅计费、平台发布、运营分析、竞品视频仿写。截图中的机器人、会员推广和个人账户不作为本期功能。完整专业时间轴编辑、剪映工程兼容为后续能力，不将示意按钮当作已实现服务。

## 成功标准

以“用户能顺畅完成并认可一部可交付短片”为首要验证目标。记录端到端耗时（人工操作与模型等待分开）、可用成片完成率、需要外部补救的环节、重复生成与返工成本，以及用户对流程清晰度和成片质量的评价。质检耗时、报告准确性仅作为阶段诊断指标。先用同类创作任务采集基线，再确定改善目标，不预设未经测量的效率提升比例。

## 原型边界

当前交付为本地可交互 PRD：数据在浏览器保存，AI 输出、TTS、视频与合成采用明确标识的示例。TXT 和图片上传、配置编辑、项目切换、历史记录、制作清单 JSON 下载是真实本地交互。目标产品的真实 AI 与编码服务仍需开发接入。


## 从零建设与实施顺序

系统从零实现，采用完整前端、后端和 PostgreSQL 数据库架构。首次工程里程碑在本地跑通“一句话 → 故事 → 剧本 → 分镜 → 参考图/配音 → 视频 → 可播放 MP4”，验证整体流程与成片可用性；已有故事入口随后复用主链路。后续部署沿用同一业务与数据模型。技术方案、模块流程图、实施顺序及上线准备见 [R5 技术实现规划](/content/reference/technical-implementation-plan.md)。本地单用户验证与公开上线分开验收，上线前补齐必要的身份校验、项目访问隔离和运行保障。

故事、剧本、分镜的 AI 质检均为修改建议，不是通行门槛。用户可采用建议生成新版，也可保留当前版本继续；报告发现问题、未就绪、调用失败或过期均不因质量结论阻断推进。继续时记录用户选择及内容/报告版本，不把报告改成“通过”。空内容、来源版本冲突、失效引用、缺失媒体等无法执行的输入仍需补齐，原因与 AI 质量建议分开展示。

## 视觉与交互验收约束

最终产品验收必须满足 [U01–U08强制验收](/content/reference/ui-interaction-acceptance.md)：四主题和最新版布局、字体、关键状态、版本/草稿安全、JSON整表刷新、键盘与适配均须有证据；工程通过不代替用户视觉与操作接受。增量按影响范围验收，不达标项不得默认延期或标通过。
